## Approach

The app is styled with **Tailwind CSS v4** (`tailwindcss: ^4`, `@tailwindcss/turbopack`) loaded via the Next.js App Router. There is no separate `tailwind.config.*` file; configuration lives in a single CSS entry point.

Styling follows a **design-token → Tailwind theme mapping → utility classes** pipeline:
1. Semantic CSS custom properties are declared as light/dark tokens in `app/globals.css`.
2. Those variables are mapped into Tailwind's `@theme inline` block so they become `color-*` utilities (e.g. `bg-primary`, `text-muted-foreground`).
3. Components compose those utilities, using `class-variance-authority` for variant-driven components and `clsx`/`tailwind-merge` via a shared `cn()` helper from `lib/utils.ts`.

Fonts are provided by `next/font/google` — Geist Sans and Geist Mono — exposed as CSS variables `--font-geist-sans` / `--font-geist-mono` and bound to Tailwind's `--font-sans` / `--font-mono`.

## Key files

- `app/globals.css` — Tailwind import, design tokens, dark-mode overrides, `@theme inline` mapping, base styles, and the `.container-page` utility.
- `app/layout.tsx` — Root layout that injects font variables onto `<html>` and applies the global `bg-background text-foreground` body class.
- `components/ui/button.tsx` — Variant-driven button built with `cva`; variants: `primary | secondary | outline | ghost | destructive | accent`; sizes: `sm | md | lg | icon`.
- `components/ui/card.tsx` — Composition of `Card`, `CardHeader`, `CardTitle`, `CardDescription`, `CardContent`, `CardFooter` following shadcn-style conventions.
- Other UI primitives under `components/ui/`: `alert.tsx`, `badge.tsx`, `field.tsx`, `input.tsx`, `label.tsx`, `select.tsx`, `spinner.tsx`, `textarea.tsx`.
- `package.json` — declares `tailwindcss ^4`, `class-variance-authority`, `clsx`, `tailwind-merge`, `lucide-react`.

## Architecture and conventions

- **Light-first palette**: tokens define a forest-green primary (`#1f6f4a`) and amber accent (`#c88a2e`) on a near-white background (`#f7f8f6`). A `.dark` selector redefines every token for dark mode.
- **Semantic token set**: `background`, `foreground`, `card`, `primary`, `secondary`, `muted`, `accent`, `destructive`, `success`, `warning`, `border`, `input`, `ring` — each with an explicit `-foreground` counterpart where needed.
- **Radius tokens**: `--radius-lg: 0.75rem`, `--radius-md: 0.5rem`, `--radius-sm: 0.375rem`.
- **Dark mode**: toggled by adding the `dark` class on `<html>` (the root layout does not do this automatically; consumers must opt in).
- **Component library pattern**: all reusable UI lives in `components/ui/`. Each component accepts a `className` prop forwarded through `cn(...)` so callers can override or extend styles.
- **Variant system**: stateful or multi-style components use `cva` (see `buttonVariants`) rather than ad-hoc conditional className logic.
- **Layout container**: a single `.container-page` utility in `@layer utilities` constrains page content to `max-width: 80rem` with horizontal padding.
- **Icons**: Lucide React (`lucide-react`) is the icon set used across the app.

## Conventions and constraints

- All colors go through the semantic token layer (`bg-primary`, `text-destructive`, etc.); raw hex values are not used in component classNames beyond the token definitions in `globals.css`.
- Every UI primitive in `components/ui/` merges user-supplied `className` via `cn()` from `@/lib/utils`, ensuring caller overrides take precedence over defaults.
- Variant-based components expose their shape through TypeScript types generated by `cva`'s `VariantProps` (as seen on `ButtonProps`), so consumers get autocomplete for `variant` and `size`.
- The root layout sets `lang="en"` and applies `antialiased` plus the Tailwind `h-full flex min-h-full flex-col` skeleton; child pages fill the remaining space via `flex-1` on `<main>`.
- Dark mode is opt-in via the `.dark` CSS selector — there is no automatic system-preference detection in the layout.
