Two-layer split inside `server/`:
- Action layer (`*.actions.ts`) — files prefixed with `auth`, `shipment`, `notification`, `quote` are marked with the `"use server"` directive and expose async functions consumed by React Server Components. They parse `FormData`, validate via Zod schemas from `@/lib/validation`, enforce auth through `@/lib/auth`, mutate data through `@/lib/db` (Prisma), and return a uniform `{ ok, error?, fieldErrors? }` shape.
- Read-service layer (`account.service.ts`, `tracking.service.ts`) — import `server-only` to guarantee they run only on the server, contain no mutation logic, and expose pure functions returning Prisma results or a discriminated union (`TrackedResult`).

Dependency direction is one-way: actions depend on services only indirectly (through shared `@/lib/*` modules like `@/lib/rating`, `@/lib/tracking-number`, `@/lib/notifications`); services never import actions. Cross-action reuse is minimal — `ActionResult` is re-exported from `auth.actions.ts` and imported by `shipment.actions.ts` and `notification.actions.ts`. Guest-facing tracking goes through `getTrackedShipment` which enforces ownership via optional postal-code/name verification before exposing public fields.
