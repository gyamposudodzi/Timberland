Two-layer hierarchy under `components/`:
- `ui/`: headless-ish primitive building blocks (`button`, `input`, `select`, `textarea`, `label`, `field`, `card`, `alert`, `badge`, `spinner`) built on Tailwind CSS and `class-variance-authority` for variant-driven styling; composed via a shared `cn` utility from `@/lib/utils`. All primitives are client components.
- Domain folders (`auth`, `account`, `quote`, `shipment`, `tracking`, `layout`, `ops`): higher-level feature components that compose `ui/*` primitives. Client-domain forms (`auth/login-form`, `auth/signup-form`, `shipment/new-shipment-form`, `tracking/track-form`) use Next.js Server Actions imported from `@/server/*` wrapped in `useTransition` for optimistic pending states. Layout components (`layout/site-header`, `layout/site-footer`) are async server components that call `@/lib/auth` to read session state and render navigation.
Dependency direction is strictly downward: domain features depend on `ui/*`; `ui/*` has no dependency on domain code or server actions. The module exposes React components only — there is no runtime logic of its own beyond presentation and form wiring.
