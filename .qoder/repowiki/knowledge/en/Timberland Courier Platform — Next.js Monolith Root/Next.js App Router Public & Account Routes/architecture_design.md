Routes follow the Next.js App Router convention with `app/layout.tsx` as the root layout providing global metadata (title template, description, `metadataBase` from `NEXT_PUBLIC_APP_URL`), Geist Sans/Mono font variables via `next/font/google`, and `<SiteHeader>` / `<main>` / `<SiteFooter>` chrome. Static/marketing segments (`/login`, `/signup`, `/pricing`, `/quote`, `/help`, `/legal`, `/verify`) are single-file async server components. The `/track/[trackingNumber]` segment is the only guest-facing dynamic route — it validates the code via `isValidTrackingNumber`, applies an IP-based rate limit through `@/lib/rate-limit`, then calls `getTrackedShipment` from `@/server/tracking.service`. The `/account/*` subtree is gated by `AccountLayout`, which awaits `auth()` from `@/lib/auth` and redirects to `/login` before rendering a sidebar nav over child pages (`dashboard`, `new-shipment`, `addresses`, `notifications`, `[id]`). The `/ops/*` subtree mirrors this pattern for operational staff. Auth wiring is centralized in `app/api/auth/[...nextauth]/route.ts`, which re-exports `handlers` from `@/lib/auth` as GET/POST. Global error boundaries (`error.tsx`, `global-error.tsx`), SEO helpers (`robots.ts`, `sitemap.ts`), shared CSS (`globals.css`), and `favicon.ico` sit at the app root alongside the route tree.
